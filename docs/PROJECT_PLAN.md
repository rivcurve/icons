# Rivcurve — план продукта, сайта и разработки

Текущая основа: **108 SVG Refined**, валидатор, каталог и экран файлов. Цель первого публичного выпуска — сайт с рабочим каталогом и три пакета из одного источника: SVG, React и Vue. Flutter выходит позже. Название Rivcurve используется в визуальных пробах как рабочее.

## 1. Сценарий первого визита

На главной разработчик понимает, что Rivcurve — библиотека иконок, видит реальный пример и переходит к подключению React или Vue через **Get started**. Каталог и поиск находятся прямо на главной. В каталоге можно найти `download`, проверить его при 16–24 px и открыть детали, чтобы скопировать импорт или SVG. Прямая ссылка на иконку ведёт к её свойствам и примеру.

| Страница | Задача | Состав |
| --- | --- | --- |
| `/` | Познакомиться с Rivcurve и сразу найти иконку | **Get started**, полный каталог с поиском, категории и размеры 16/20/24. Демо и инструкции ниже. |
| `/icons/` | Поддержать старые ссылки | Переход к каталогу на главной с сохранением параметров поиска. |
| `/icons/<id>/` | Дать постоянную ссылку | Название и варианты, размер и тема, разметка и скачивание SVG. На широком экране допускается панель деталей, на узком — отдельный экран с возвратом к поиску. |
| `/docs/` | Подключить пакет и использовать его в продукте | Quick start, SVG, React, Vue, доступность и управление размером/толщиной, правила вклада и журнал выпусков. |
| GitHub | Посмотреть исходники или предложить правку | README, исходники, лицензия, шаблоны заявок, выпуски и правила вклада. |

В каталоге имя совпадает с ID иконки. Категория и запрос сохраняются при переходе в детали и обратно. При пустом результате есть очистка фильтров. Копирование даёт короткое подтверждение, при отказе браузера выделяемый текст остаётся доступен. Для ссылок, кнопок и вкладок предусмотрены клавиатура, видимый фокус и доступные имена. На телефоне поиск остаётся доступным без перехода через меню. Размеры значков и зоны нажатия задаются отдельно.

Рабочий язык сайта и документации — английский. Кнопки подключения ведут в документацию. Ссылки GitHub указывают на репозиторий, пока доступный участникам проекта. Число иконок берётся из каталога, а не из макета.

## 2. Система бренда

До реализации выбираем одно визуальное направление. Для каждого оцениваем знак при 16 px, читаемость названия, первый экран, поиск и превью небольших иконок. Картинки служат эталоном композиции и визуального языка. Геометрия сайта берётся из канонических SVG, а брендовый знак после выбора перерисовывается в SVG и проверяется в одном цвете.

В выбранной системе понадобятся логотип, отдельный знак, favicon, аватар репозитория, обложка README и шаблон карточки релиза. Зафиксируем шрифты и их лицензии, цвета для светлой и тёмной тем, размеры, сетку, размещение иконок, стиль документации и правила применения знака.

## 3. Архитектура и границы

Один репозиторий, один набор SVG, один манифест со стабильными ID. Генерация создаёт структуру каталога, модули компонентов, типы и опубликованные SVG. Сайт читает те же метаданные и проверяется с той же версией набора.

| Часть | Планируемый путь | Контракт |
| --- | --- | --- |
| Исходные иконки | `icons/<style>/<category>/<id>.svg`, `icons.json` | SVG 24×24, контур 2, округлённые концы, `currentColor`. Манифест задаёт ID, стиль, категорию, ключевые слова и при необходимости отражение RTL. |
| Нормализация и генерация | `scripts/`, `generated/` | Детерминированная сборка. Проверка на дубликаты, устаревшие выходные данные и потери в геометрии. |
| Веб-пакеты | `packages/svg`, `packages/react`, `packages/vue` | Статические экспорты и файлы по иконкам. Контролируемые зависимости, типы и проверка импорта из упакованного архива. |
| Сайт | `apps/site` | Next.js App Router со статической сборкой, локальный поиск, переходы на страницы иконок и документация. |
| Flutter | `packages/flutter`, отдельный этап | SVG в ресурсах и типизированная обёртка. Тот же ID. Цвет, размер и семантика на стороне Flutter. |

Публичный веб-контракт: `GitBranchIcon` в React и Vue, размер 24 и толщина 2 по умолчанию. У декоративной иконки нет собственного имени, у смысловой есть доступное имя. Кнопка с одной иконкой получает имя на самой кнопке. Формы SVG и брендовые файлы отделены.

### Первый срез Next.js

- `apps/site/app/page.tsx` показывает все SVG и каталог с поиском, а `/icons/` перенаправляет к каталогу на главной. Клиентская часть читает локальный манифест.
- `apps/site/app/icons/[id]/page.tsx` заранее генерирует страницу каждого известного ID. Сборка сайта статическая. Первый выпуск не требует собственного API, базы данных, регистрации или внешнего поиска. [Статическая сборка Next.js](https://nextjs.org/docs/app/guides/static-exports).
- Поиск считает точный ID первым, затем ищет по началу ID и синонимам. Основной пример для приёмки — `download`. Пользователь должен найти символ в каталоге прямо на главной, увидеть его при 16 или 24 px и скопировать SVG из деталей. Действие не зависит от доступности GitHub или npm.
- Первые маршруты документации — `/docs/`, `/docs/react/` и `/docs/vue/`. На приватном стенде каждая страница явно показывает статус пакета. После выпуска она ссылается на опубликованный пакет.

## 4. Порядок работ и признаки готовности

1. **Выбор направления.** Согласовать визуальный макет и рабочее имя. Остальные картинки сохраняются как варианты. До открытия репозитория повторить проверку имени. Для начального закрытого репозитория зарезервировать `vend1k12/rivcurve` и `/Users/vend1k/Work/rivcurve`, если оба пути свободны.
2. **Перенос текущей базы.** Создать приватный репозиторий личного аккаунта, клонировать в Work, перенести SVG, документы и валидатор. В первый коммит входят исходники и выбранный план. Проверить владельца, статус private, локальный путь и удалённый адрес.
3. **Один законченный путь через сайт.** Главная → Get started → пример React/Vue. Второй путь: поиск `download` на главной → детали → копирование SVG или просмотр импорта. Использовать канонические SVG. Принять адаптивность и работу с клавиатуры до расширения на остальные страницы.
4. **Доводка Refined.** Варианты и новые символы рисовать сериями. Сначала навигация, действия в таблицах и финансовые сценарии. До 14 новых действий по дорожной карте. Сравнить 12 общих символов с Phosphor при одинаковом размере и цвете. Фиксировать правки по ID.
5. **Пакеты и документация.** Собрать SVG, React и Vue. Проверить реальные архивы в двух чистых приложениях, сравнить визуальную геометрию, убедиться, что импорт одной иконки не добавляет весь пакет. Сайт и пакеты получают одинаковые данные.
6. **Приватная бета.** Дать сборку на просмотр и пройти контрольные маршруты: поиск с нулём результатов, прямая ссылка, мобильная ширина, переключение темы, копирование и пример установки. Перепроверить названия пакетов и статус лицензии.
7. **Публичный веб-выпуск.** После согласования правообладателя, MIT и решения об открытии репозитория опубликовать каталог, архивы и npm-пакеты из одного тега. Для релиза хранить команды сборки, журнал изменений и результаты проверок.
8. **Flutter после веб-выпуска.** Сначала прототип на 8–12 иконках с дугами, прямоугольниками, несколькими контурами и семантикой. Проверить Android и iOS, вес приложения и рендер при 16/20/24. Затем сгенерировать весь набор и подготовить выпуск на pub.dev.

Полный [план релизов](ROADMAP.md) содержит критерии для каждого этапа. Текущая версия плана не назначает даты. Сначала оцениваем работу по выбранному визуальному направлению и стартовому срезу сайта.
