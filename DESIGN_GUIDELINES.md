# Refined · правила дизайна иконок

Refined — рабочее название стиля. Его основа — ровный контур, плавные скругления, ясные силуэты и минимум деталей. Библиотека предназначена для продуктовых интерфейсов и не привязана к фирменному стилю конкретного продукта.

В исходном обсуждении утверждён визуальный лист из 50 иконок. Из связанного чата восстановлено описание стиля. Сверка геометрии и состава с самим изображением остаётся отдельным этапом.

## Контракт исходного SVG

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <path d="M10 6l6 6-6 6"/>
</svg>
```

- Холст 24×24. Масштаб задаёт место использования. В исходнике оставляем `viewBox` и опускаем `width` и `height`.
- Линия шириной 2 единицы центрируется по контуру. Круглые концы и соединения задаются один раз на корневом элементе. При размере 16 px линия масштабируется до 1⅓ px, при 20 px до 1⅔ px, при 24 px до 2 px.
- Исходник содержит только элементы геометрии SVG. Используй `path`, `circle`, `ellipse`, `rect`, `line`, `polyline` и `polygon`, когда соответствующий примитив делает форму понятнее.
- Рисуй фигуры на общей сетке. Используй целые координаты для горизонталей и вертикалей в размере 24 px, дробные — для оптической центровки или плавной кривой. Задавай координаты с точностью, необходимой для сохранения силуэта.
- Цвет наследуется через `currentColor`. Значения цвета, `style`, отдельные переопределения толщины, растровые вложения, маски, фильтры, трансформации и внешние ссылки в исходнике исключены.
- Один файл описывает одну иконку. Имя файла — устойчивое английское существительное или действие в `kebab-case`. Семантику конкретного экземпляра определяет приложение.

## Геометрия

| Свойство | Правило |
| --- | --- |
| Рабочая область | По умолчанию размещай осевые линии в пределах 3–21. Крайние оси 2 и 22 допустимы для круглых, диагональных или широких форм, если того требует видимый баланс. Окрашенная область с учётом линии остаётся внутри 1–23. |
| Контуры | Для небольших деталей начни с радиуса 2. Для крупных оболочек используй радиус 3–4, когда он сохраняет характер формы. Углы стрелок остаются читаемыми благодаря круглым соединениям. |
| Просвет | Цель для раздельных параллельных линий — от 2 единиц чистого просвета, то есть 4 между осями при линии 2. Сужения на кривых и диагоналях оцени на 16 px. Намеренные стыки рисуй без случайных коротких зазоров и удвоения линии. |
| Оптическое положение | Для симметричных фигур начинай с центра `(12, 12)`. Для фигур с тяжёлой стороной оцени распределение массы визуально. Небольшое смещение допустимо, если на общем листе иконка выглядит ровнее и сохраняет поля. |
| Детали | Сначала силуэт, затем один основной отличительный признак. Дополнительные штрихи оправданы, если без них теряется смысл. Удали элементы, которые на 16 px сливаются с контуром или выглядят как грязь. |
| Семейства | Варианты одного объекта делят базовый силуэт и размеры характерных частей. Проверяй рядом стрелки, документы, профили и остальные соседние понятия. |

Рисуй вектор вручную или редактором на сетке. Растровый лист задаёт характер и смысл, геометрию строим из примитивов. Оцени сходство с референсом по силуэту, оптическому весу и характеру кривых.

## Почерк Refined

Отправная точка для новых форм — одобренная итерация с `home`, `user`, `wallet`, `chart-bar`, `folder-open` и `git-branch`.

- Дай форме один характерный жест. У папки это плавная ступенька клапана, у диаграммы — широкий поворот общей оси, у ветки Git — плавный отвод от вертикали.
- Повторяй конструктивные элементы внутри семьи. У закрытой и открытой папки одинаковые левый край и клапан. У линейного графика и столбчатой диаграммы общий контур осей. У вариантов профиля одинаковые плечи с коротким горизонтальным участком.
- Оставляй воздух вокруг смысловых деталей. Значки действий у профиля держи отдельно от силуэта. У разнесённых частей сначала проверяй границу на 16 px, затем уточняй кривую и пропорции при увеличении.
- Для поиска нового характера начни с силуэта и продумай, как он продолжится в соседних иконках. Смотри на небольшое семейство рядом перед переносом решения в каталог.

## Проверка в интерфейсе

- **16 px.** Силуэт узнаваем без увеличения. Основные отверстия, стрелки, индикаторы и зазоры различимы. Если деталь мешает, сначала упрощай форму.
- **20 px.** Проверь выравнивание рядом с текстом, равномерность линии на диагоналях и цельность семейства.
- **24 px.** Проверь поля, пропорции, скругления, стыки и переходы кривых.
- На каждом размере посмотри светлый и тёмный фон при обычном масштабе страницы. Линии должны оставаться различимыми на реальном интерфейсном цвете. Дополнительно проверь иконки рядом друг с другом.

## Доступность

- Декоративная иконка рядом с видимым текстом скрыта от скринридера через `aria-hidden="true"` в месте использования. Внутри кнопки с одним значком доступное имя получает кнопка, например `aria-label="Удалить файл"`.
- Самостоятельная смысловая иконка получает `role="img"` и доступное имя через `aria-label` или `aria-labelledby`. При использовании SVG как `img` имя передаётся через `alt`; для декоративного изображения используй `alt=""`.
- Обозначай состояния формой или текстом. Смысловой графике нужен контраст с прилегающим фоном. Для интерактивного значка размер области нажатия задаёт элемент управления.
- Не записывай общее `title` или `aria-hidden` в исходный файл. Компонент или интерфейс может задать контекст, локализовать название и избежать повторного чтения.

При работе с цветом учитывай способ подключения. Вставленный в разметку SVG наследует `color` от окружения. Для SVG, подключённого через `img`, цвет внутри файла не наследуется с внешней страницы.
