# Техническое задание · набор иконок Refined

Собери первый набор самостоятельной библиотеки. Работай в стиле Refined по [DESIGN_GUIDELINES.md](DESIGN_GUIDELINES.md). Результат этапа — редактируемые исходные SVG, стабильный каталог, повторяемые проверки и локальный предпросмотр.

Утверждённое изображение из исходного чата задаёт ожидаемый характер форм. Пока доступно его текстовое описание, приведённый ниже инвентарь считается рабочим. После получения изображения сопоставь символы и пропорции с листом, отметь расхождения и обнови исходники по итогам сверки. Имена и наличие отдельных символов не считай подтверждёнными по изображению.

## Изменение и сборка

1. Отредактируй SVG на сетке 24×24. Для варианта существующего символа начни с его базовой формы. Для нового ID внеси имя и категорию в `icons.json`.
2. Запусти `python3 scripts/icons.py build`. Сборка валидирует источники, формирует `generated/icons.json` для генераторов компонентов и автономный `preview.html` для браузера. Одинаковые исходники дают одинаковый результат. Автоматические артефакты обновляй командой сборки.
3. Запусти `python3 scripts/icons.py check`. Проверка сверяет файлы с манифестом, обнаруживает повторяющиеся ID и проверяет XML, обязательные атрибуты SVG, допустимые элементы, их атрибуты и актуальность артефактов. Ошибка завершает команду с ненулевым кодом и показывает файл или запись каталога.
4. Открой `preview.html?qa` и проверь сводку по размерам, цвету и границам SVG. Проведи визуальную проверку по таблице ниже. При исправлении формы повтори сборку и проверку.

Исходные файлы задают геометрию. Манифест задаёт имена, категории и порядок. Утилита первого этапа использует стандартную библиотеку Python и запускается из корня проекта. Геометрические отклонения, смысл, оптический баланс и читаемость оценивай по визуальной проверке, даже если структура SVG проходит автоматически.

## Визуальная проверка

| Что смотреть | Как принять |
| --- | --- |
| 16, 20 и 24 px на светлом и тёмном фоне | Проверить иконки из манифеста в реальном размере. На каждом фоне силуэт различим, независимые части не слипаются, скругления остаются плавными. |
| Окрашенные границы | Сверить консервативную оценку в браузере. К координатам прямоугольника `getBBox()` добавить по 1 единице с каждой стороны и проверить диапазон 1–23 по обеим осям. Вручную проверить поля и видимый силуэт. |
| Семейства | Сопоставить `arrow-left` и `arrow-right`; `user` и его варианты; `file` и `file-text`; `folder` и `folder-open`; `git-branch`, `git-commit`, `git-pull-request`. Проверить одинаковый визуальный вес и различимость. |
| Сложные знаки | На 16 px отдельно проверить `users`, `currency-exchange`, `database`, `bug`, `command`. При слипании упростить детали или развести линии. |
| Сверка с изображением | Сравнить конкретный силуэт и положение в наборе, когда доступен утверждённый лист. Зафиксировать несовпадения с точным ID. |

В отчёте укажи результат команд, просмотренные размеры и фоны, а также ID найденных проблем. Снимок увеличенного листа полезен для геометрии, для читаемости смотри ещё и настоящий размер.

## Контракт для React и Vue

Два генератора на следующем этапе будут читать один `generated/icons.json`. Оба используют один набор фигур, одинаковый порядок и одинаковые значения корневых атрибутов. Записывай имена компонентов детерминированно по правилу `file-text → FileTextIcon` и проверяй коллизии после преобразования.

В каждом пакете предусмотрен отдельный TypeScript модуль на иконку и статические именованные ESM экспорты. Тест сборки для импорта одной иконки должен подтвердить удаление остальных модулей. Общие свойства компонента задают размер, цвет и толщину, по умолчанию 24, `currentColor` и 2. У компонентов единое поведение доступности из гайдлайна, с возможностью передать видимое или доступное имя там, где его требует интерфейс. Генераторы и выпуск пакетов относятся к следующему этапу. Перед открытой публикацией выбери лицензию, добавь текст лицензии и укажи правообладателя.

## Критерии готовности

- Все ID уникальны, каждая категория содержит хотя бы одну иконку. Для каждой записи манифеста есть один SVG и одна запись в сгенерированных данных.
- Все SVG открываются, используют `viewBox="0 0 24 24"`, контур `currentColor` толщиной 2 и скруглённые стыки и концы. Фигуры остаются редактируемыми.
- Проверка и сборка проходят, повторная сборка сохраняет те же данные и предпросмотр. Каталог открывается локально без установки зависимостей браузерной части.
- Визуальная проверка на 16, 20 и 24 px пройдена; известные расхождения перечислены по ID. Сверка с утверждённым изображением фиксируется отдельно.
